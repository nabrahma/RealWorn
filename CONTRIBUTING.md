# Contributing to RealWorn

Thanks for your interest in RealWorn. Bug reports, ideas and pull requests are all welcome.

- **Bugs and ideas:** open an [issue](https://github.com/nabrahma/RealWorn/issues). The templates
  ask for what we need to reproduce a problem: Blender version, OS and GPU, and the steps.
- **Questions and show-and-tell:** use
  [Discussions](https://github.com/nabrahma/RealWorn/discussions) when it is enabled, or an issue.
- **Security problems:** please don't open a public issue. See [SECURITY.md](SECURITY.md).

Everyone taking part is expected to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Setting up

You need Blender 5.2 LTS or later, Python 3.11 or later, and git.

1. Fork and clone the repository.
2. Point the scripts at your Blender. Either set `BLENDER_BIN` in the environment, or create a
   `.env` file at the repository root:

   ```sh
   BLENDER_BIN=/path/to/blender
   ```

3. Install the test dependencies (pytest and Hypothesis) for Blender's bundled Python. They go
   into `tests/_vendor/`, never into your Blender installation:

   ```sh
   "$BLENDER_BIN" --background --factory-startup --python scripts/setup_test_env.py
   ```

4. Optional: download the CC0 Poly Haven materials used by the round-trip and reference tests.
   Tests that need them are skipped until they are there.

   ```sh
   python tests/corpus/fetch.py               # real-material corpus
   python tests/corpus/fetch.py --reference   # texture sets for the reference wall test
   ```

5. To try your changes in Blender:
   1. Add a Local extension repository (Preferences > Get Extensions > Repositories).
   2. Point it at a folder that contains a link to `realworn/`.
   3. Enable RealWorn.

## Running the tests

```sh
pip install pytest hypothesis
python -m pytest tests/pure                                                  # fast, no Blender
"$BLENDER_BIN" --background --factory-startup --python tests/run_tests.py    # everything in Blender
"$BLENDER_BIN" --background --factory-startup --python tests/run_tests.py -- -k decals
```

- **What CI runs:** the pure tests on every push and pull request. Please run the Blender suite
  locally before opening a pull request. It takes about 25 minutes, mostly the GPU performance
  tests; use `-k` to run the tests for the area you changed.
- **Outputs:** renders and performance logs go to `tests/_out/`.
- **Performance tests:** they record real numbers. A budget that isn't met is marked as an expected
  failure with the measured value, never relaxed.

## How the code is organised

| Path | What |
| --- | --- |
| `realworn/core/` | The engine: compiler, injector and snapshot, setup, images, bake, migration |
| `realworn/operators/`, `realworn/ui/` | Operators, the sidebar panel, the paint overlay and pie menu |
| `realworn/builders/` | Code that generates the bundled grunges, damage alphas and decals |
| `tests/` | Blender tests, `tests/pure/` (plain Python), fixtures |
| `scripts/` | Packaging, asset generation, test environment setup |

## Design rules

These rules keep RealWorn safe for people's work. Pull requests that break them can't be merged.

1. **The layer list is the source of truth.** `material.realworn.layers` is authoritative.
   - Only `core/compiler.py` creates or deletes nodes inside `RW_Stack::<material>`.
   - Only `core/injector.py` touches a material's top-level node tree.
   - Value changes update node inputs; structural changes recompile.
2. **Remove must stay exact.** Setup followed by Remove restores the original material tree, slots
   and UV maps exactly. The round-trip tests in `tests/test_core_setup.py` must keep passing.
3. **Painted masks are the user's work.** Never delete, resize destructively or overwrite a mask
   image without an explicit user action, and never let a save lose paint.
4. **Masks are sampled through the `RW_Paint` UV map only.** Never modify the user's own UV maps.
5. **Use Blender's own texture paint and brush system.** RealWorn creates its own brush assets and
   never edits the user's.
6. **Core code takes explicit datablocks, never `bpy.context`,** so it runs headless and can be
   tested.
7. **All property and attribute names come from `realworn/core/naming.py`.**
8. **No hand-edited binary assets.** Images and node setups are generated by Python in
   `realworn/builders/`; rebuild them with the `scripts/make_*.py` scripts.
9. **The reference wall test defines what "correct" looks like.**
   - `tests/fixtures/reference_wall.py` builds the look by hand with plain Blender nodes.
   - If a change makes RealWorn differ from it, fix RealWorn; don't change the reference.
10. **Check Blender 5.x APIs before using them.** Many changed from 4.x. Verify node types, socket
    names and enums against the current API docs or a running Blender.

## Pull requests

- **One topic per pull request.** Small and focused is easier to review.
- **Tests:**
  - Add or update tests with the change.
  - For a bug fix, a test that fails without the fix is ideal.
- **Commit messages:** use [Conventional Commits](https://www.conventionalcommits.org/) style:
  - `feat:`, `fix:`, `perf:`, `refactor:`, `docs:`, `test:` or `chore:`;
  - a short title in the imperative;
  - a plain description of what changed and why.
- **User-visible changes:** add a line to the Unreleased section of [CHANGELOG.md](CHANGELOG.md).
- **Code from another project:**
  - It must be GPL-3.0-compatible.
  - Keep its licence header and add a comment naming the source file and commit.
  - Add an entry to [THIRD_PARTY.md](THIRD_PARTY.md).
